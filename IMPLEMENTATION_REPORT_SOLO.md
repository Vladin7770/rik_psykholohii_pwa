# Режим «Навчайся самостійно»

19 листопада 2026 року. Реалізація в локальному репозиторії; публікацію на Vercel не виконано.

## Аудит перед змінами

Аудит і план надано в розмові до першого редагування коду.

- Статичний SPA/PWA на звичайному JavaScript. `index.html` містить UI, hash-router, звичайні модулі, стан та навчальні інструменти. Node.js 22 і esbuild збирають статичний `dist/`; Vercel публікує цю директорію. Supabase Auth не синхронізує навчальні записи.
- Стан — `S`. `fresh()` / `norm()` доповнюють відсутні поля, `validateState()` перевіряє завантаження та імпорт; `mutate()` / `saveLocal()` записують зміни з перевіркою конфлікту вкладок.
- Сховище — localStorage `psykholohiia-rik-v1`, формат `v:1`. Пошкоджений оригінал зберігається, автоматичний запис блокується, інтерфейс відкривається з чистим тимчасовим станом. Оригінал можна завантажити; валідний імпорт відновлює запис.
- Маршрути — `#overview`, `#modules`, `#m1`–`#m12`, `#study?material=…` та маршрути інструментів. Окремий академічний шар — `#academic`, `content/curriculum.js`, `content/academic-core.js`, `content/academic-ui.js`.
- Звичайні модулі — `MODS`. Старі теми — масиви рядків; прогрес і нотатки прив’язані до `номерМодуля-індексТеми`, індекс від нуля. Кількість тем: **6, 7, 7, 7, 7, 7, 9, 7, 8, 8, 8, 7**.
- Матеріали — єдина `S.library` з `module` / `topicKey`, стабільними ID та `resourceStates`. Старі `materials` / `topicMaterials` збережені. Наявна форма — `matform`, нотатки тем — `topicNotes`.
- Питання — `quiz[номерМодуля]`, результати — `quizResults[номерМодуля]`. Є тренувальний тест і контрольна. Налаштування розміщені на сторінці «Сьогодні».
- Експорт включає весь `S` у JSON-обгортці версії 1. Імпорт приймає обгортку й старий сирий стан, перед заміною зберігає попередній стан у `psykholohiia-rik-v1-pre-import`.
- Автоматичні перевірки — Node/VM, ізольовані DOM, сховище, час, таймери та кеші; тести Auth/build і перевірка академічного контенту. Початковий результат — **340 перевірок**: 180 попередніх + 160 node:test.

## План і виконання

1. Додати необов’язковий режим із типовим guided та перемикач у чинні налаштування. Виконано; перевірено старі стани/копії й перемикання без зміни навчальних записів.
2. Додати окрему таблицю результатів для модуля 1 та власні результати/відмітки. Виконано; шість тем мають по два результати. Решта модулів показують «Результати ще не додано» й форму власного результату. Наповнення інших модулів потребує лише даних у `TOPIC_OUTCOMES`.
3. Додати solo-подання модуля й теми. Виконано; джерела використовують наявну модель і форму з вибраною темою. «Своїми словами» використовує `topicNotes`. Власна вправа та її результат автозберігаються без перемальовування поля. Підказка показує лише «Порівняй · наведи приклад із життя · поясни типову помилку». Готовий огляд, джерела й практична робота містяться у згорнутому пункті «Підказки: готові матеріали».
4. Розширити чинний тест. Виконано; перед питаннями — необов’язкова відповідь із пам’яті. Для дострокового старту показуються попередження та явна кнопка. Порожній банк пропонує написати питання. Поріг — 1–100%, типовий 70%. Навіть одна власна відповідь із вибором дозволяє провести solo-контрольну; у guided збережений мінімум із трьох питань.
5. Обчислювати завершення та повернення до складних тем. Виконано; головна показує поточний модуль, наступну незавершену тему з результатами та теми, до яких настав час повернутися.

Після кроків запускалися наявні перевірки; знайдені регресії форм усунено. Кількість перевірок після кроків 1/2/3/4/5: 343/345/347/350/357; фінальне посилення перевірок — 361.

## Нові дані

Усі поля необов’язкові. Типові значення кореня задають `fresh()` / `norm()`, полів теми — адаптер читання `soloTopic()`. Невідомі кореневі й вкладені поля зберігаються.

| Поле | Тип | Значення за відсутності |
|---|---|---|
| `studyMode` | `'guided'` або `'solo'` | `'guided'` |
| `quizPassThreshold` | ціле число 1–100 | `70` |
| `soloTopics` | об’єкт за ключем теми | `{}` |
| `soloTopics[key].outcomes` | масив `{id: string, text: string}` власних результатів | `[]` |
| `soloTopics[key].outcomeChecks` | об’єкт `id → boolean` | `{}`; відсутня відмітка — `false` |
| `soloTopics[key].exercise` | рядок, до 6000 символів | `''` |
| `soloTopics[key].exerciseResult` | рядок, до 12000 символів | `''` |
| `soloTopics[key].difficultAt` | timestamp у мілісекундах | `0` — складність не позначена |
| `soloTopics[key].reviewDueAt` | timestamp у мілісекундах | `0` — повернення не заплановано |
| `quiz[module][i].module` | номер модуля | модуль зі старого ключа колекції; старе `0` теж успадковує ключ |
| `quizResults[module].examBest` | число 0–100, найкраща контрольна | для старого `examPassed: true` підтверджено попередній поріг 70%; вищий поріг потребує нової контрольної |
| `quizResults[module].lastMode` | `'practice'` або `'exam'` | невідомо; старий результат не переозначується |
| `quizResults[module].lastThreshold` | ціле число 1–100 | відсутнє; попередній типовий поріг 70% |
| `toolDrafts['solo-recall:'+module].text` | рядок, відповідь із пам’яті | `''` |

`TOPIC_OUTCOMES[key].outcomes` — окрема необов’язкова таблиця авторських масивів рядків у коді; за відсутності — порожній масив. Вона не змінює `MODS.topics`. Власні результати мають стабільні ID `own-…`, авторські — `builtin-0`, `builtin-1`; у формі можна довести загальну кількість результатів теми до трьох. Нове авторське наповнення не видаляє вже записані власні результати.

Джерела зберігаються у чинній `library`, конспект — у чинній `topicNotes`. Подкасти мають чинний тип «Інше». Для нової книги дозволено порожній URL; інші нові джерела потребують коректної http(s)-адреси. Дубльованої колекції матеріалів немає.

## Завершення і сумісність

Solo-модуль завершений, коли всі теми опрацьовані, кожна тема має щонайменше один результат і всі результати відмічені, у кожній темі записані непорожні вправа та результат її виконання, а найкраща контрольна досягла поточного порогу. Тренувальний тест цього не замінює. Порожній список результатів не зараховується як засвоєння.

Завершення обчислюється з доказів; старий `done` не переписується. У guided знову використовуються його старі позначки. Підвищення порогу або зняття відмітки може зробити solo-модуль незавершеним, зберігаючи всю історію. Старий `examPassed` підтверджує проходження при порозі до 70%; старе `best` не вважається балом контрольної, бо воно включало тренування.

Складна тема отримує строк `зараз + 7 × 24 години`. На головній вона показується від цього моменту; після кнопки «Повторив» строк переноситься на сім днів. Зняття складності прибирає нагадування. Це локальний список, без системних push-повідомлень.

Позиції й розкриті панелі guided у `moduleViews` не перезаписуються solo-поданням. Параметри шрифту й теми спільні; окрема позиція прокручування solo не зберігається. Посилання на тему відкриває її результати вгорі.

Ключ сховища, `v:1`, формат backup, порядок і тексти **всіх 88 тем** незмінні. Еталон тем узято з `HEAD` до змін і збережено в тестовій fixture. Нових залежностей і змін lockfile немає. SW отримав нову базову версію; чинний build fingerprint включає змінений HTML.

## Перевірки та межі

Фінальні команди виконано напряму Node.js 22.19.0: `npm` відсутній у PATH. Це ті самі перевірки, що перелічені в `package.json`.

```sh
node tests/learning-tools.test.cjs
node --test tests/auth.test.mjs tests/build.test.mjs tests/academic.test.cjs tests/study-workspace.test.cjs tests/solo.test.cjs
node scripts/validate-academic.cjs
node scripts/build.mjs
git diff --check
```

**361 успішна перевірка, 0 помилок:** 180 попередніх + 181 node:test, включно з 21 новою перевіркою solo. Перевірка контенту, production build і `git diff --check` успішні.

Автоматично перевірено старий стан і старі формати копій; збереження всіх початкових полів fixture; експорт/імпорт усіх нових полів у чистий стан; guided → solo → guided; порожнє/пошкоджене сховище; відмову запису й конфлікт вкладок; індекси/порядок тем; автозбереження; умови завершення; поріг; достроковий тест; часову межу повернення. Для всіх 12 solo-модулів і фаз тесту перевірено збалансовану розмітку, унікальні ID й підписи полів у світлому та темному налаштуванні. Тести не читають особисте сховище.

**Реальну браузерну консоль, візуальне відображення на 360 px і темну тему перевірити не вдалося:** інструмент повернув `The browser access host is unavailable`, доступних браузерних поверхонь немає. DOM/VM-перевірки не замінюють візуального QA. Адаптивні правила й токени залишені чинними; для довгих власних текстів додано перенесення, для прапорців — збереження розміру. На фізичному пристрої не перевірялися клавіатура, фокус, встановлення та оновлення PWA. Збірка виконана без Supabase-конфігурації; production OAuth не перевірявся.

Перед випуском: відкрити локальний `dist` у браузері на 360 px, пройти guided → solo → guided в обох темах, додати джерело/вправу, перевірити достроковий і звичайний старт тесту, імпортувати стару копію, експортувати нову й імпортувати в чистий профіль; перевірити консоль. Функціональні пункти 1–5 реалізовано; авторське наповнення результатів модулів 2–12 залишене порожнім відповідно до запиту.
