# Архітектура навчальних інструментів

Базова версія: Git `d1e5926`; до змін пройшли всі 130 перевірок `tests/stage6.test.cjs`. Іконки 192×192 та 512×512 присутні. Користувацька зміна `.DS_Store` не входить до роботи.

Навчальна частина залишається статичним SPA. Для Auth додано офіційний Supabase SDK та esbuild як засіб збірки. Єдине джерело даних — `S`, ключ `psykholohiia-rik-v1`, формат `v:1`. Нові колекції та налаштування отримують defaults у `fresh()` / `norm()`, проходять `validateState()` і потрапляють до чинної резервної копії. Невідомі поля не видаляються. Усі записи проходять через `mutate()` / `saveLocal()` із перевіркою конфлікту вкладок.

Наявні `studyResume`, `moduleViews`, `moduleBookmarks`, Command Palette, `S.concepts`, `S.research`, `S.caseNotes` та навчальні таймери розширюються на місці. Нові hash-маршрути використовують той самий router. Чернетки форм зберігаються в `toolDrafts`, окремо від завершених записів, із прив’язкою до типу та ID редагованого запису. Збереження не перемальовує поле під час введення.

Експерименти використовують лише тимчасовий стан взаємодії й локальну історію результатів. При приховуванні вкладки вимірювання припиняється; продовження починає поточну пробу заново. Результати не є клінічними вимірюваннями.

Режим читання змінює CSS та зберігає налаштування, використовуючи чинне відновлення позиції. Навчальні сесії використовують наявний таймер `T` та його облік хвилин; режим без таймера не створює штучного часу чи XP.

App shell збирається у `dist/`: HTML, manifest, дві іконки, локальний `auth.js` та згенерований `runtime-config.js`. Оновлення service worker очікує явної дії, зберігає стан і відмовляє за наявності незбереженої форми або помилки сховища.

## Supabase Auth

Клієнт — `src/auth-client.mjs`, контролер — `src/auth-controller.mjs`, UI — `src/auth.mjs`. Збірка бере тільки `SUPABASE_URL` та публічний `SUPABASE_ANON_KEY`; секретні ключі відхиляються. SDK працює як єдиний `window.rikSupabase`, UI/API доступні через `window.RikAuth`. `onAuthStateChange` синхронний; перевірка `getUser()` відкладена поза callback і захищена від застарілих відповідей.

SDK зберігає сесію під `rik-psykholohii-auth:<supabase-origin>`, поза `S` та навчальними JSON-копіями. При холодному офлайн-запуску SDK відкладається, щоб не запускати refresh expired-токенів; збережений профіль служить лише підказкою UI. Після повернення мережі створюється клієнт і виконується перевірка. Вихід має scope `local` і не очищає навчальних даних.

Навчальні записи залишаються локальними та спільними для акаунтів цього браузера. Ця інтеграція не додає таблиць або хмарної синхронізації. Перед OAuth зберігаються чинні форми/позиція; незбережені інші форми блокують редірект. PKCE повертається на поточний origin через query-параметр без конфлікту з hash-router.

Повна інструкція й перевірки — [SUPABASE_SETUP.md](SUPABASE_SETUP.md). `vercel.json` тепер публікує `dist`, а build fingerprint оновлює SW після зміни коду або env.

## Академічний шар 2.0

Канонічні дисципліни, нові семантичні ID, авторські тексти й бібліографічні статуси — `content/curriculum.js`. Чисті правила — `content/academic-core.js`; UI через адаптер `content/academic-ui.js`. Збірка перед копіюванням запускає content gate; усі три файли входять у fingerprint і атомарний офлайн-кеш.

До `S` додається необов’язкове `academic` зі `schemaVersion:1`, ізольованими curricula та станом за lessonId. Ключ і коренева v:1 незмінні. Старі модулі не перенумеровуються; старий прогрес не вважається доказом нової компетентності. Невідомі поля та записи інших версій зберігаються. Дані уроків відокремлені від чернеток і спроб.

Фейнман, дослідження, концепти, щоденник, ідеї, картки й календар отримують необов’язковий academicLessonId, не підміняючи старі module/topicKey. Запис проходить через чинні mutate/saveLocal та перевірку конфлікту вкладок. Буфер 450 мс скидається перед навігацією, експортом, імпортом, OAuth та update. Повний опис і межі — IMPLEMENTATION_REPORT_ACADEMIC.md.

У редакції Модуля 1 `videos` є реєстром конкретних зовнішніх ресурсів; `videoGuides` зберігає власний український супровід, а `reviewUnits` — матеріал для редагованих карток. Чернетки відповідей до відео використовують той самий буфер. Картки отримують необов’язковий `academicUnitId` лише після явного створення. Відеофайли й плеєри не включені в app shell.

`evidence(lesson, record)` обчислює результати за `attempts[].contentVersion`: нова редакція не успадковує доказ опанування старого коротшого тесту. Історичні спроби, кореневі дати, конспекти й самопозначені етапи зберігаються. Після першого успіху в поточній редакції відкладена перевірка призначається через два дні. UI використовує докази поточної редакції; самопозначення етапів не є перевіркою знання.
